# Known limits and unresolved acceptance

Alchemy is a working local customer-trial application with implemented provider adapters. It is not a verified hosted service, and the complete V5 acceptance gate is not met.

## Account-dependent acceptance

Supabase application authentication, real independent users and behavioral access enforcement, hosted OpenAI API model access, hosted Inngest recovery, Gemma evidence review, ElevenLabs microphone/voice/disconnect and inbound phone routing, Google Calendar booking, Twilio SMS delivery, Resend email delivery, and deployed share/invite/revocation all remain unverified. The separate Alchemy hosted schema has migrations 001–009 applied; structural RLS, API/function grants and private-bucket settings were checked against the actual project. Those checks do not establish scoped app sessions or private file transfer. Configured code, mocked tests and embedded PostgreSQL are separate evidence. No public deployment is available. Real local Codex task receipts are recorded separately in `artifacts/local-agent-proof.json`; they do not prove the hosted API path. The user authorized live email/SMS/calendar tests, but provider setup and exact destinations are still required before executing them.

## Product boundaries in this build

- The Alchemy Site URL and exact localhost callback are saved, without wildcard redirects. The default Supabase authentication email is a magic link; the current dashboard requires custom SMTP to edit it into a code template. No paid upgrade, Send Email hook, new provider or weaker security setting was activated. Local publishable/service keys remain pending and application login is unverified.
- Private upload/download adapters, scoped customer task updates and scheduled in-app reminders are implemented and SQL-tested. The actual hosted bucket is private and its size/MIME restrictions were verified; upload/download through authenticated application sessions, customer sessions and job recovery have not been verified.
- Trial results use source-backed manual observations; there is no automatic telemetry or external invoice/payment confirmation. Task completion evidence remains separate from a measured target.
- Full backups and tested restoration, delivery monitoring and a production operational runbook remain release gates.

- Imported text and CSV create editable records. Frontdesk separately reads bounded public websites and parses text, Markdown and text PDFs. Scanned PDFs are rejected explicitly. Source-bound model extraction requires owner review; it is not unrestricted web research. CRM/email inbox sync, telemetry connectors, billing connectors and customer environment provisioning are not implemented.
- Frontdesk's real local model extraction was verified against fictional business documents. Exact quotation validation establishes source matching, not semantic correctness. Owners must verify facts and fill gaps before the operating brief is approved. Approved knowledge is not automatically pushed into an ElevenLabs agent, and a configured phone-number variable is not proof of inbound connectivity.
- Calendar credentials are bound server-side to one configured program. Google free/busy checks and event insertion cannot atomically prevent another application from creating an overlapping calendar event. Durable Alchemy reservations protect its own concurrent booking path. SMS requires separate consent; uncertain submissions are not automatically repeated.
- Customer email automation uses reviewed rules and authenticated customer report links. Send-only keys support signed Resend delivery webhooks; without a webhook, API polling needs read access. Signature/timestamp and saved provider ID/sender/recipient matching are tested locally, but an actual provider event has not been received. Provider acceptance is not delivery, delivery to the recipient mail server does not establish inbox placement or an opened message, and reply detection is not implemented. A changed trial plan requires fresh message review. Hosted scheduler recovery and real provider receipts are still required.
- JSON reimport creates corrections only for supported matching partner fields. It is not a complete historical archive restore; exports retain the full serialized state for inspection.
- Work can represent per-account setup as separate items/dependencies. The application does not automatically decompose a shared integration into per-account deployment tasks.
- The request/work graph is explicit and founder-reviewable. A genuine Smith run produced source-checked reuse and classification findings; proposals remain subject to founder review. No canonical source contradiction was invented.
- Changes conservatively stale all saved plans when the planning input hash changes, including changes outside a selected scenario. Fine-grained per-field dependency invalidation is not implemented.
- Audit history retains action/version/actor/time. Sources, agreement amendments, correction proposals and decision snapshots retain their respective evidence; arbitrary manual field edits do not have a complete before/after event-sourced replay. There is no general replay player.
- The Agents workspace displays stored actual execution states and validated results. Trial pages remain stable while those supporting tasks run.
- No consenting intended-founder study occurred. Demand, willingness to pay, business savings, conversion improvement and judge preference are unknown.
- The original videos are truthful recordings of the earlier local demo interface. Current screenshots show the Cosmos-inspired interface and real local Codex results. The original videos do not show the redesigned UI or verify Gemma/ElevenLabs. Captions use scene/chunk timing rather than forced word alignment. Human listening and subjective delivery polish remain a review step.

These limits are disclosed so the handoff does not confuse implemented local behavior, adapter code, and real external proof.
